Нажмите значок в строке меню, чтобы открыть Kairos. Повторное нажатие или щелчок вне панели скрывает её. При повторном открытии в рамках того же запуска сохраняются страница, введённые данные и результаты проверок.

App Control и DNS Control — отдельные вкладки. В Network Tools собраны диагностика и обслуживание, в Settings — настройки сервисов, разрешения и журналы. В About можно посмотреть версию и проверить обновления. Инструменты и редакторы сценариев открываются как вложенные страницы той же панели; кнопка возврата ведёт на предыдущую страницу.

Интерфейс приложения поддерживает английский, упрощённый и традиционный китайский. По умолчанию используется язык macOS; выбрать другой можно в Settings → General. Изменение вступает в силу после перезапуска Kairos.

## Сетевые сценарии

Kairos отслеживает изменения сетевого пути и получает IP-адрес и MAC-адрес шлюза по умолчанию. Сценарий срабатывает, только если оба значения в точности совпадают с включённым правилом.

- Сценарий управления приложениями может закрыть перечисленные приложения при активации правила. После смены сценария приложения, которые больше не управляются, запускаются снова.
- DNS-сценарий может применить к текущему интерфейсу заданный основной и необязательный резервный DNS. Это выполняет привилегированный DNS Helper.
- Сценарий не является профилем прокси. Kairos не создаёт, не редактирует, не выбирает и не применяет настройки прокси. Для этого используйте свой прокси-клиент.

Данные шлюза, по которым выполняется сопоставление, видны в приложении; их можно скопировать в правило для доверенной сети.

Глубокая очистка временно отключает Wi-Fi, очищает кэш DNS и ARP, сбрасывает интерфейс, удаляет кэш Chrome и Firefox, затем выполняет финальную системную очистку. Соединение обычно прерывается примерно на 2–5 секунд.

## DNS Helper и разрешения

Для изменения DNS и глубокой очистки требуется отдельный LaunchDaemon `SMAppService`, устанавливаемый Kairos. Зарегистрируйте его в Settings, введите пароль администратора по запросу macOS и подтвердите в Системных настройках, если это потребуется. Helper умеет задавать и очищать DNS-серверы, сбрасывать кэш DNS и выполнять привилегированные этапы обслуживания.

Разрешение «Универсальный доступ» нужно, когда сценарий управления приложениями должен завершить другое приложение. Без него Kairos всё равно может наблюдать за сетью. Kairos автоматически заменяет ядро Mihomo только по доступному пользователю для записи пути вне пакета приложения; защищённые расположения требуют ручной обработки.

## Mihomo

Резервное копирование, восстановление и замена ядра находятся в Network Tools → System Maintenance. Связанное приложение, путь к ядру, URL GitHub Releases и шаблон имени файла задаются в Settings → Services.

Kairos не содержит клиента Mihomo и не управляет правилами прокси. Клиент и файл ядра выбираете вы. Kairos может создать резервную копию и восстановить этот файл, а также скачать из URL GitHub Releases последний prerelease, соответствующий шаблону имени файла; адрес по умолчанию — `vernesong/mihomo`. Перед заменой ядра приложение попросит завершить связанный клиент.

## Данные IP и ключи API

Поиск IP, введённого в приложении, отправляется в [ipapi.is](https://ipapi.is). Проверка качества IP сначала получает публичный IP через `api64.ipify.org`, `checkip.amazonaws.com` или `icanhazip.com`, затем параллельно отправляет этот IP источникам ниже. Тест DNS напрямую отправляет выбранные доменные имена проверяемому резолверу.

Поиск IP также использует ключ ipapi.is, сохранённый в настройках. Без ключа текущий лимит — 30 запросов в сутки по UTC на публичный IPv4-адрес или IPv6 /64; ответ содержит только базовые сведения о владельце и местоположении. Отсутствующие данные отображаются как «—», карта появляется только при наличии координат. С ключом возвращается полный ответ в пределах квоты аккаунта. Актуальные условия приведены в [документации сервиса](https://ipapi.is/developers.html).

| Источник | Без ключа | С собственным ключом |
|---|---|---|
| IPinfo, ipapi.is, DB-IP, IPWHOIS | Kairos использует доступный бесплатный endpoint сервиса. | При наличии используется endpoint сервиса с ключом. Для IPinfo настроенный токен сразу выбирает официальный endpoint, без токена используется widget endpoint. Ошибки запросов отображаются пользователю. |
| AbuseIPDB, IP2Location, ipregistry | Пропускается. | Добавляется к проверке качества IP. |

Добавляйте ключи в Settings, только если нужны источники с ключом или более высокие лимиты. Kairos хранит их локально в `UserDefaults` и не использует собственный сервис-посредник. Экспорт настроек в `.kairos` включает ключи API, сценарии и настройки Mihomo; считайте этот файл конфиденциальным и не передавайте его другим.

Ответы провайдеров используются для показа местоположения, ASN/организации, типа сети и доступных сигналов приватности или злоупотреблений. Данные разных провайдеров могут расходиться и не являются вердиктом безопасности.

## Установка

### Homebrew

```bash
brew tap slippindylan/tap
brew trust --tap slippindylan/tap
brew install --cask kairos
```

### DMG

Скачайте последний DMG из [GitHub Releases](https://github.com/SlippinDylan/Kairos/releases), откройте его и перетащите `Kairos.app` в `Applications`.

Релиз подписан сертификатом Apple Development, но не нотариально заверен Apple. macOS добавляет атрибут quarantine к приложениям, скачанным из интернета, поэтому Gatekeeper может заблокировать первый запуск. Если вы доверяете релизу, удалите атрибут после копирования приложения:

```bash
sudo xattr -rd com.apple.quarantine /Applications/Kairos.app
```

## Требования и сборка из исходного кода

- macOS 26.0 Tahoe или новее
- Apple Silicon (arm64)

Для локальной сборки нужны macOS 26 или новее и Xcode 26 или новее. Откройте `Kairos.xcodeproj` и запустите scheme `Kairos`. Debug использует локальную подпись ad hoc без входа в Apple Account; привилегированные функции Helper требуют подписи приложения и Helper действующим сертификатом одной команды. Подробнее — в [инструкции по локальной разработке](development.md).
